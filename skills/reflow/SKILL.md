# Build with Reflow

On the Reflow showcase, read `/llms.txt` for the documentation index. Follow its Markdown links for component imports, examples, and the full props reference. Each docs page also has a **View as Markdown** link.

Inspect the project's package manifest and existing UI before making changes. Use the installed Reflow exports and types as the API reference. In the Reflow workspace, read `packages/reflow/src/index.ts`, the relevant source module, and its examples in `apps/web/app/public/component-demos.tsx`. When changing the library itself, follow its code structure in `docs/scope.md`: each component in its own file, shared headless logic in `src/behaviors/`, shared look and motion in `src/systems/`, explicit named exports in `src/index.ts` (never `export *`), and component styles imported into `src/styles.css` (built into one `@layer reflow` stylesheet). Keep `apps/web/app/docs-data.ts` aligned with exported prop types (`docs-api.test.ts` checks names and requiredness).

Reflow uses the Remix 3 component runtime. Component setup runs once and returns a render function. Read changing props through `handle.props`, update local state in events, and call `handle.update()`. Browser interactions require a hydrated client entry. Follow the installed Remix documentation for unfamiliar APIs.

## Composition

Import components from `@rtzll/reflow` (or specialist entries: `@rtzll/reflow/markdown` for `Markdown` & `MarkdownEditor`, `@rtzll/reflow/highlight` for `highlight()`, `@rtzll/reflow/diffs` & `/diffs/ssr` for `DiffView` / `prerenderDiff()`, `@rtzll/reflow/trees` & `/trees/ssr` for `FileTree` / `prerenderFileTree()`, `@rtzll/reflow/diagrams` & `/diagrams/ssr` for `Diagram` / `prerenderDiagram()`) and load `@rtzll/reflow/styles.css` once in the document head — or load only the domain stylesheets you need (`@rtzll/reflow/core.css` plus any of `/chat.css`, `/code.css`, `/projects.css`, `/diffs.css`, `/trees.css`, `/diagrams.css`, `/markdown.css`). Every stylesheet sits in `@layer reflow`, so unlayered app CSS and Remix `css()` styles override it; put broad resets in an earlier layer (`@layer base, reflow, rmx, app;`). When using optional peer packages (`@pierre/diffs`, `@pierre/trees`, `pele`) in client entries, include them in `assets.allowPackages` in `remix.json`.

### Forms and inputs

Prefer the existing form-aware controls and preserve labels, descriptions, reset behavior, disabled options, keyboard navigation, and focus return.

- Use `Button` for actions and links (`href`), `SplitButton` for a joined primary action and attached `Dropdown` menu (e.g. Squash and merge / Rebase), `InlineEdit` for click-to-edit titles with Enter/Escape semantics, `Field` / `FieldSet` for accessible label, description, and error wiring, `Input` and `Textarea` for text entry, and `InputGroup` / `InputField` for grouped fields.
- Use `InputCopy` for copyable values (API keys, commands, URLs) so clipboard feedback stays inside the field.
- Use `Checkbox` and `Switch` for single booleans (`Switch` supports dragging as well as clicks), `CheckboxGroup` for multi-select lists, and `RadioGroup` for mutually exclusive lists with descriptions.
- For one choice among a few short options in a row, such as a view or time range, use `SegmentedControl`; `Tabs` switch between panels.
- Use `Select` for fixed option lists (supports `group` on `ChoiceOption`) and `Combobox` when the user should filter, pick multiple values as chips (`multiple`), or create new options (`creatable`).
- Use `NumberField` for typed quantities with native form validation and step buttons; enable `scrub` for values users adjust repeatedly. Use `Slider` for bounded continuous or discrete ranges (single value or `[min, max]`).
- Use `FileInput` for uploads in a form. Set `accept` and any count or size limits, and read the native file values from `FormData`.
- Use `FilterBar` for tokenized `key:value` facet search bars with removable chips, inline key/value autocomplete (`suggestions`), free-text terms, and one-click `presets` (reusing `parseFacetQuery`).

### Date and color

- Use `Calendar` for inline single-date or range selection (`mode="range"`), `DatePicker` when the calendar opens from a field (with optional presets, `time`, or `timeRange`), and `TimeField` for standalone wall-clock times (`HH:mm` values, flexible typing, `step`, `after` with durations, `hourCycle`, and `name` form submission).
- Use `TimeGrid` for appointments in one or more day columns. Supply stable event IDs, day indexes, and wall-clock minutes. Set `stepMinutes` to the booking increment, apply `onEventChange` to accept a move or resize, and use `onCreate` to open an editor or reserve the selected interval. Keep dates, timezones, availability checks, and persistence in the owner. Mark holidays, deadlines, and trips `allDay` (with `span` for several days) instead of giving them a 24-hour slot; an event whose duration runs past midnight continues in the next column on its own. Pass `onCreateAllDay` to let a drag across the all-day strip open your editor with the days covered.
- Use `ColorPicker` inline or as a popover (`variant="popover"`) for hex, RGB, HSL, and OKLCH editing with swatches, opacity, and form submission (`name`).

### Navigation and disclosure

- Use `Sidebar` for application navigation rails with collapsible sections, nested rows (`href` omitted on expandable parents), search (`searchable`), resizing, and a mobile modal drawer; use `variant="inset"` with the `toolbar` slot for an inset app shell.
- Use `Breadcrumb` for page hierarchy trails with optional step menus (`menu`) and overflow collapse (`collapse`).
- Use `Accordion` for collapsible disclosure sections (`type="single"` or `"multiple"`, `variant="grouped"` or `"separated"`).
- Use `Tabs` to switch between content panels.
- Use `Pagination` with a one-based `page` and an `href` function returning real URLs (keep current-page state in the route for bookmarks and history), or `onPageChange` for local paging.
- Use `Toolbar` for grouped actions that share a single tab stop; arrow keys move between buttons or links while text fields keep their own tab stops.
- Use `Tree` for expandable hierarchies with selection. Give every item a unique `value` and use the selected leaf to drive an adjacent preview.
- Use `Resizable` for two panes that share space, or `ResizableGroup` for 3+ panes (e.g. FileTree | DiffView | Inspector) with collapsible side panels that remember their restored width. Name separators, supply bounds, and use `onValueCommit` / `onValuesCommit` to persist layouts.
- Use `VirtualList` (backed by `computeVirtualRange` / `scrollOffsetForIndex`) for large fixed-height commit lists, PR queues, or log tables with deterministic SSR and native scrolling.
- Use `ShortcutSheet` (backed by `createKeymap` / `attachKeymap` for single keys and `g p`-style chords) for a searchable keyboard shortcut dialog toggled via `?`.
- Use `RelativeTime` for hydration-safe `<time>` labels that render deterministic UTC dates on the server, live relative timestamps on the client, and exact UTC timestamps in a `Tooltip`.
- Build GitHub-class code review and CI screens with `DiffStat`, `ProportionBar`, `MetadataList`, `CopyChip`, `StackGraph` (stacked PR DAG), `MergeReadiness` (expandable PR merge-gate card), `DiffMinimap` (viewed progress + Next unviewed / Next unresolved jumps), `CodeBrowser` (Shift+Click `#L42-L58` line anchors + toggleable git-blame heat gutter), `TestReport` (pass/fail/flaky explorer with diffs and stack traces), `MatrixGrid` (2D OS × runtime CI matrix with arrow-key nav), `MergeQueue` (speculative merge train), `SizeDelta` (bundle/artifact budget deltas), and `ActivityHeatmap` (SVG calendar heatmap with keyboard scrubbing).
- Build Linear-style project & issue tracking workspaces with `groupItemsBy` / `placeGroupedItems` / `createUndoStack` (`behaviors/group-placement.ts`), `FloatingActionBar` (contextual bulk toolbar), `ViewOptionsPopover` (Display menu), `InlinePropertyPicker`, `ProgressRing`, `PriorityIndicator`, `StatusIcon`, `LabelChip` / `LabelPicker`, `EstimatePill`, `SavedViewTabs`, `KanbanBoard` (WIP limits, collapsible rails, drag + Alt+Arrow moves), `GroupedList` (sticky headers, `j`/`k` nav, Shift-range select), `QuickCreateBar`, `RoadmapTimeline` (zoomable Gantt + milestones), `CycleOverview` (ring + workload + burndown), `SubIssueList`, `RelationList`, and `TriageQueue` (single-key Accept/Duplicate/Snooze/Decline inbox).
- Use `Carousel` for a row of slides rather than a hand-built slider: it scrolls natively, snaps, drags with momentum for mice, and autoplays through `CarouselDots` with a pause button; name slides with `slideLabels`.

### Menus and overlays

- Use `Tooltip` to name a control in a few words, `HoverCard` to preview what a link or name points to without taking focus, and `Popover` for controls the user opens with a click.
- Use `Dropdown` for action and option menus (including `checkbox`, `radio`, and `switch` rows, `hint`, `badge`, `note`, submenus, `searchable`, `openOnHover`, and `variant="bare"` for custom triggers such as sidebar rows).
- Use `ContextMenu` for actions on focusable rows. Set `target` to a selector for eligible descendants and use the element passed to `onSelect` to identify the row. Pass a function `(target) => DropdownItem[]` to `items` when actions should be tailored per row. Users can right-click or press Shift+F10. Pass `shortcuts` to `ContextMenu` (or `rowActions.shortcuts` to `DataTable`) so those keys run the item for the focused row; otherwise display only shortcuts the application handles itself.
- Use `CommandMenu` for searchable command palettes (inline or modal with `trigger` and `shortcut`, optional `filters`, `suggestions`, and opt-in `footer`).
- Use `Dialog` for modal tasks (`flush` lets a child composition such as a sidebar fill the panel and visually hides the title), and `AlertDialog` when the user must confirm a destructive action (`Cancel` receives initial focus).
- Use `Drawer` for small-screen navigation, filters, and side details: it is a modal dialog that slides in from an edge and closes with a drag, so keep a footer action when it must not be dismissed. For a bottom sheet that opens part way, pass `snapPoints` such as `[0.4, 0.9]` rather than sizing it yourself; `scaleBackground` pushes back the element marked `data-rf-drawer-background`.

### Display, feedback, and data

- Use `Card` and `CardGroup` for grouped content surfaces (clickable cards require `label`), `Badge` for compact status or category tags, and `Kbd` for single keys or platform-aware shortcut chords (`keys="mod+k"`, `variant="subtle" | "outline"`, optional `separator`).
- Use `Banner` for lasting inline or fixed status notices. Confirm transient actions with `Toaster` and `toast()` / `toast.success()` / `toast.promise()`: place one `<Toaster>` in the app, give it an action such as Undo rather than asking first, and keep blocking problems in a `Banner` or `Dialog`.
- Use `Avatar` for people, teams, and agents, and `AvatarGroup` for several at once; mark an avatar decorative when the name is written beside it.
- Use `Progress` for work in flight (supply `value` and `total` when known; omit `value` when indeterminate), `Spinner` for indeterminate loading (give a standalone spinner a `label` and omit it when nearby content names the status), and `Skeleton` for decorative placeholders sized to match incoming content (set `aria-busy` on the loading region).
- Use `CodeBlock` to show code: highlight it with `highlight()` from `@rtzll/reflow/highlight` where the code is known (ideally in a route handler or build step so the browser loads no Shiki), and mark lines with `// [!code highlight]`, `++`, `--`, or `focus` comments.
- Use `Terminal` for command and CI output in `CodeBlock`'s quiet frame with zero-dep ANSI SGR colors (`parseAnsiLine`, `stripAnsi`), status badges, live search filtering (`searchable`), `follow` auto-scrolling, and plain-text copy.
- Use `Timeline` for vertical connected commit, review, check, or activity feeds with semantic tones (`neutral`, `accent`, `success`, `warning`, `danger`), metadata chips, timestamps, and detail blocks.
- Use `EmptyState` for centered zero-match or empty-queue placeholders with an optional framed icon tile, description, and recovery actions (`surface="plain" | "outlined"`).
- Render structured prose and assistant replies with `Markdown` from `@rtzll/reflow/markdown` (optional standalone CSS at `@rtzll/reflow/markdown.css`). Render it on the server when text does not stream so the page loads no parser. Pass accumulated text as `source` while streaming. Fences use `CodeBlock` (override via `renderCodeBlock`, e.g. to render `mermaid` fences with `Diagram`), pipe tables use `Table`, and raw HTML appears as text. Images render as links by default; pass `images` only for same-site images or an allowlist of hosts you control, never arbitrary hosts in generated replies.
- Render Mermaid architecture and flow diagrams with `Diagram` from `@rtzll/reflow/diagrams` (backed by the optional `pele` peer dependency, with synchronous `prerenderDiagram()` from `@rtzll/reflow/diagrams/ssr`, standalone CSS at `@rtzll/reflow/diagrams.css`, and live `--rf-*` CSS-variable theming).
- Render virtualized repository/diff file trees with `FileTree` from `@rtzll/reflow/trees` (backed by the optional `@pierre/trees` peer dependency, with `prerenderFileTree()` from `@rtzll/reflow/trees/ssr` for zero-flash Declarative Shadow DOM SSR, standalone CSS at `@rtzll/reflow/trees.css`, folder compaction, git status, and colored `rowDecorations`). Use core `Tree` for lightweight non-code hierarchies.
- Visualize CI pipelines, build timings, and execution logs with `LogViewer` (Datadog-style grouped collapsible steps, ANSI SGR colors, severity stripes & filter pills, severity volume histogram via `showHistogram`, plain/regex/`key:value` facet search with removable active facet chips, expandable structured `fields` drawers, error jumping with `n`/`p`, timestamps, Shift+click line ranges, `maxVisibleLines` large-log windowing, follow-tail), `Waterfall` (hierarchical job/span timing bars on a shared time axis with critical-path emphasis), `PipelineGraph` (interactive job dependency DAG with measured SVG Bezier connectors and path highlighting), and `StatusStrip` (compact duration-scaled run-history strip with hover/selection readout).
- Use `DataTable` when readers need to filter, sort, or page through records (supply stable `rowKey` and columns with comparable `value`). Use `RoutedDataTable` with `route` for shareable URL state. Pass `freezeRowHeader` to keep the identifying column visible during horizontal scrolling, and `rowSelection` (with optional `selectAllMatching` and server `rowCount`) for bulk actions. Keep `Table` for short, hand-authored tables. Custom lists can reuse `createRangeSelection()` for Shift+arrow ranges.
- Use `BarChart` for quantities per category: negative values hang below zero, `series` with per-item `values` shows several quantities (`layout="stacked"` for totals), and `orientation="horizontal"` suits long labels. Supply stable item IDs and short labels; give drill-down bars an `href` for server-rendered links or `onSelect` for local actions, and omit both inside a static card link.
- Use `Sparkline` for compact inline trend lines (with semantic `tone`, optional `fill`, and `interactive` pointer/keyboard scrubbing), `MetricCard` for KPI and runner telemetry summaries (combining tabular values, `delta`/`deltaTone`, `badge`, and inline `sparkline`), `LineChart` for responsive multi-series time-series and area charts with dashed baselines and crosshair scrubbing, and `ObjectInspector` for collapsible structured JSON/event payload trees with type-colored primitives, circular-reference protection, and one-click JSON copy.

### Conversation and agent UI

- Build a chat screen with `ChatLayout`: messages as its children and `InputMessage` as its composer. `ChatLayout` keeps the reader pinned to the newest message, so do not scroll the transcript manually; pass `busy` while a reply streams, and `scroll="anchor"` when replies run long so the reader's question stays near the top while the answer grows below it.
- Render turns with `ChatMessage` (use `role="system"` for conversation events such as a model switch or resumed session). Use `ChatOutline` beside or above a long transcript so readers can jump between turns.
- Use `InputMessage` for message composition with optional `attachments`, `voice` recording (`voiceShortcut`), `pasteAsFile`, caret `triggers` (or standalone `TriggerMenu` on a textarea), and message queuing (`queue` / `showQueue`) backed by `QueuedStack`.
- For long-form GitHub/Linear-style discussions and code reviews, use `MarkdownEditor` from `@rtzll/reflow/markdown` (Write / Preview / Split modes, formatting toolbar with Mermaid and code-suggestion snippets, optional `TriggerMenu` mentions, `renderCodeBlock` hook for live `Diagram` previews, and `Mod+Enter` submit) alongside `CommentThread` and `ReactionBar` (compact `fluidHover()` pill reactions with active toggle state and an anchored `+` picker).
- Show image or file attachments with `FileThumbnail` (images preview directly; PDFs and other files render a readable card with name and type).
- Show agent work in progress with `ThinkingIndicator` (short cycling status), `ThinkingSteps` (expandable reasoning timeline with details, sources, and images), `ToolCalls` (a folded one-line summary of tool calls with elapsed time and per-call status), `TaskList` (read-only plan steps as not started, in progress, or done), `FileChanges` (summary card of edited files with line additions/removals and show-more folding), `DiffView` from `@rtzll/reflow/diffs` (backed by the optional `@pierre/diffs` peer dependency for syntax-highlighted unified or split diffs from `diff`, `oldFile`/`newFile`, or `fileDiff`, with `prerenderDiff()` from `@rtzll/reflow/diffs/ssr` for zero-flash Declarative Shadow DOM SSR, `copyable`, `collapsible`, `headerPrefix`, `enableGutterUtility`, and slotted Remix `renderAnnotation`), and `CommentThread` (threaded review discussions with `Avatar`, optional suggested code changes, inline replies, and spring-collapsed Resolve/Reopen, usable standalone or inside `DiffView` annotations).
- Before an agent runs a command, sends something, or edits files, ask with `Confirmation` rather than a `Dialog`: phrase `title` as the question, name the buttons after the action, and use `status="warning"` for risky actions; it keeps the answer itself unless `state` is controlled, and `name` submits it with a form.
- For multi-step structured clarification from the user, use `AskUserQuestions` (supports single/multi choice, custom answers, skipping, and form submission).
- Cite sources in generated text with `Citation` chips right after the claim they support; give each source a title and link, and an excerpt where available.

Apply theme settings on a common ancestor with `data-theme`, `data-accent`, `data-shape`, `data-density`, and `data-hover`. Use the `--rf-*` CSS properties from the installed stylesheet for surfaces, spacing, text, and focus colors. Consumers can provide icons as slots without adding an icon runtime.

## Interaction craft

- Use one moving hover surface for a group. `fluidHover()` attaches to the host, rows use `data-rf-hover-item`, and its surface uses `data-rf-hover-layer`. A selection surface remains distinct from pointer hover. Do not move focus just because the pointer moved.
- Reserve the width of active labels so increasing their font weight does not move adjacent controls. Keep icons and success feedback in stable slots.
- Contract a button surface by a fixed pixel on press. Scaling the whole button distorts wide controls. Use the library's Button implementation.
- Let a transition reverse when input changes. Reuse the shared motion settings and respect reduced motion. Avoid adding bounce to quiet form controls.
- Keep clipboard feedback inside the existing field. Copy only after a user action. Report failure if access is denied.
- Pause explanatory demo loops when the user interacts, when off screen, and when reduced motion is requested. Keep all demonstrated controls usable with the keyboard.

When reviewing an interface, identify the concrete interactions that users will notice and improve those within the requested scope. Verify changes at their normal entry points, including keyboard, theme and density variants. Credit Fluid Functionalism when adapting its designs or source and preserve license notices.
